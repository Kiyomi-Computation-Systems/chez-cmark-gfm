# Design Spec: Stage 6 — Packaging, Documentation, and Release (release 1.0)

- **Status:** Accepted
- **Date:** 2026-08-18
- **Scope:** Milestone 6; ships as release **1.0** per ADR-0007
- **Related:** [project plan](chez-cmark-gfm-sxml-project-plan.md) §14, §15 (M6), §16 · [design spec](2026-08-16-chez-cmark-gfm-design.md) §6.6, §8 · ADR-0001, ADR-0002, ADR-0003, ADR-0004, ADR-0007 · ADR-0014 (new, this stage)

## 1. Scope

Stage 6 is the packaging and release milestone. It adds no rendering, parsing, or
mapping behavior: **1.0 freezes the API**. The single public-API change is one
additive condition accessor, and it exists to make an unbuilt tree diagnosable.

**Exit criterion** (plan §15, M6; design spec §8): a clean machine installs and
exercises every public API from the documentation alone.

**In scope:**

- A checked-in fallback `(cmark gfm private config)` so an unbuilt tree raises a
  structured condition instead of a loader error, plus a `reason` field on
  `&cmark-shim-unavailable`.
- `examples/` — six runnable programs, `make examples`, and an export-coverage gate.
- `tests/test-stress.sps` — accumulation across iterations, and pathological
  document shapes below the limits.
- Documentation: the CI-proven support matrix, an ownership contract, the
  static-versus-dynamic linking paragraph plan §14 requires, a `NOTICE` carrying
  the native dependency's license, and the Akku install caveat from design spec §6.6.
- A clean-machine CI job in a bare container.
- Version 1.0.0, a CHANGELOG entry, ADR-0014, retroactive `v0.2.0`/`v0.3.0` tags,
  and `v1.0.0`.
- An audit of plan §16's fifteen acceptance criteria (§8 below).

**Out of scope, explicitly:**

- Publishing to the Akku archive. The manifest is a declaration; see §2.
- Runtime-read configuration (the successor design; ADR-0014 records it).
- A `docs/` folder of in-depth documentation. README additions here stay **terse**;
  depth is deliberately deferred to a later `docs/` tree.
- A GitHub Release.
- Windows (ADR-0004), every plan §18 future-work item, and any new renderer,
  option, node type, or policy.

### 1.1 The install contract for 1.0

The supported install is **clone + `make build` + `CHEZSCHEMELIBDIRS=src:fallback`**.
That is the path CI proves on every push, and 1.0 claims nothing beyond it.

Akku installation is left *reachable* rather than *supported*. Two seams are kept
open deliberately: `CHEZ_CMARK_GFM_SHIM` already resolves the shim from the
environment, and the fallback config makes an installed-but-unbuilt tree fail with a
condition that names the remedy. Closing the remaining gap is ADR-0014's successor
design, not this stage's work.

## 2. Why the fallback config exists

An unbuilt tree fails like this, reproduced against a copy of `src/` with the
generated file removed:

```text
Exception: library (cmark gfm private config) not found
```

That names nothing actionable. It does not mention `make build`, does not mention the
shim, and is not a condition any caller can `guard` on. It is Chez's loader reporting
a missing file, which is the correct report of the wrong fact: the file is absent
because the tree was never built, and the project knows how to say so.

`src/cmark/gfm/private/config.sls` is generated by `make build` and gitignored,
carrying a `GENERATED by make -- do not edit, do not commit` banner
(`Makefile:346`). It holds machine-specific absolute paths. None of that changes.

### 2.1 Layout

```text
fallback/cmark/gfm/private/config.sls   NEW   checked in; same library name, same 3 exports
src/cmark/gfm/private/config.sls        unchanged: generated, gitignored, banner intact
src/cmark/gfm/private/conditions.sls    EDIT  &cmark-shim-unavailable gains `reason`
src/cmark/gfm/private/native.sls        EDIT  resolve-shim-path clause; reasons at 3 raise sites
src/cmark/gfm.sls                       EDIT  export cmark-shim-unavailable-reason
Makefile                                EDIT  CHEZ_LIBDIRS := src:fallback:tests:$(SRFI_LIBS)
                                              new targets: examples, check-config
```

Chez resolves a library from the **first** `CHEZSCHEMELIBDIRS` entry that has it.
Verified empirically: with two directories each defining `(demo probe)`, `a:b`
yields `from-A` and `b:a` yields `from-B`. So `src` preceding `fallback` means the
generated config shadows the fallback whenever a build has happened, and the
fallback is reached only when it has not.

### 2.2 `shim-path` is `#f`, and that is the whole mechanism

The fallback defines `shim-path` as `#f` — not a string, not a fake path, not prose
stuffed into a path field. No build can produce a non-string there, which makes it a
sentinel the failure path cannot fake. This is AGENTS.md's own rule applied to a
value rather than an assertion: `#f` is dangerous as an *expected* value precisely
because so many failures produce it, but it is ideal as a *marker* no success
produces.

`resolve-shim-path` (`native.sls:64`) already raises `&cmark-shim-unavailable` when
the configured default is not a regular file, so the load path needs no new logic —
only one leading clause mapping a non-string default to reason `'not-built`.

### 2.3 The `reason` field

`&cmark-shim-unavailable` currently carries `path` alone, so four distinct failures
are indistinguishable to a caller. It gains `reason`:

| reason | raised when |
|---|---|
| `not-built` | the fallback config is in force; no `make build` has run |
| `missing` | the generated default path is not a regular file |
| `invalid-override` | `CHEZ_CMARK_GFM_SHIM` is set but is not an absolute path to an existing regular file |
| `load-failed` | `load-shared-object` raised on a file that passed validation |

This mirrors `&cmark-invalid-option`, which already carries `key` + `reason`, so it
is the house convention rather than a new idea. Adding an accessor is additive for
existing `guard` clauses; the constructor's arity change is internal.

`invalid-override` deliberately covers three causes at once — an empty string, a
path not starting with `/`, and an absolute path that is not an existing regular
file — because `resolve-shim-path`'s single `else` branch already conflates them
(`native.sls:74`). Splitting them would mean restructuring a `cond` in the load path
this release exists to freeze. The conflation is recorded in §11.

### 2.4 `cmark-library-paths` is `'()`, and the asymmetry is documented

The fallback's `cmark-library-paths` is empty. A consequence follows and is accepted
rather than fixed: in an unbuilt tree, setting `CHEZ_CMARK_GFM_SHIM` to a prebuilt
shim works on macOS, whose loader searches a dlopen'd library's dependencies, and
fails on Linux, where it does not (`native.sls:91`, the asymmetry CI already
caught once). Making that symmetric means an environment override for the cmark
library paths — a second config mechanism, new public surface, in the release meant
to freeze the API. It belongs to ADR-0014's successor design. The README states the
limitation.

### 2.5 Drift control

Two files now declare `(cmark gfm private config)`, and nothing would notice them
diverging. That is the exact shape of the bug `check-pins` exists for — a rule about
two artifacts staying equal, violated in the same commit that wrote it down as a
comment.

`make check-config` asserts that the fallback and the generated config declare the
same library name, export the same set of names, and carry the same
`cmark-supported-version-range` literal. It runs in CI immediately after
`make build`, in both existing jobs, because it can only compare against a generated
file that exists.

### 2.6 Testing the fallback needs a subprocess

A built tree always shadows the fallback, so no in-process test can reach it.
`tests/test-shim-loading.sps` already spawns Chez against a synthetic
`CHEZSCHEMELIBDIRS` and is the precedent; the new case points at a copy of `src`
with `config.sls` removed, plus `fallback`, and asserts the raised condition's
reason is `'not-built` — compared against that symbol, not against truthiness.

## 3. Examples and the coverage gate

### 3.1 The programs

| File | Public API it exercises |
|---|---|
| `examples/01-rendering.sps` | `markdown->html`, `->commonmark`, `->plaintext`, `->xml`; wrap width; safe-by-default |
| `examples/02-options.sps` | `make-cmark-options`, `default-cmark-options`, `cmark-options-with`, accessors, `supported-extensions`, limits |
| `examples/03-ast.sps` | `markdown->ast`, `default-ast-options`, node accessors, `markdown-node-map`/`-fold`, source positions |
| `examples/04-sxml.sps` | `markdown->sxml`, `markdown-ast->sxml`, `make-sxml-options` and accessors |
| `examples/05-errors.sps` | `guard` over the `&cmark-error` family and its accessors |
| `examples/06-capabilities.sps` | `cmark-gfm-version`, `-version-compatible?`, `-available-extensions` |

Each is a `--program` script that prints. `chez --program` exits **255** on an
uncaught exception and **0** clean (verified), so the runner needs no exit-status
scaffolding — this is not the SRFI-64 trap documented in AGENTS.md.

### 3.2 `make examples`

Runs each program and diffs its output against `examples/expected/NN.out`, failing
on the first mismatch and reporting which.

It sets `CHEZSCHEMELIBDIRS=src:fallback` and **nothing else** — no
`build/scheme-libs`, no `chez-srfi`, no `wak-*`. This converts the 0.3.0 CHANGELOG
claim that a consumer acquires no dev dependencies into something that breaks the
build if an example ever reaches one.

### 3.3 The gate

`tests/test-example-coverage.sps` is pure Scheme — it touches no shared object and
joins `make check-purity` as a fourth entry. It reads the export list out of
`src/cmark/gfm.sls` with `read` (verified: importing only `(rnrs)`, since
`with-input-from-file` is already exported there — the same conflict class
`native.sls` documents for `file-exists?`), giving **83 identifiers**. It then reads
each `examples/*.sps` **as datums, not as text**, and fails if any export appears in
no example.

Reading rather than scanning text matters: a `grep` over source would be satisfied
by an identifier that appears only inside a comment, which is documentation of
nothing. `read` discards comments by construction.

Three properties keep the gate honest:

- **Exemptions are declared with reasons**, in a checked-in list. Today it holds
  `&cmark-dead-document` and `cmark-dead-document?`: raised only from private
  `scope.sls` (`scope.sls:40,157`) and unreachable through the public API. AGENTS.md
  requires exactly this — an uncoverable property is written down, never left silent.
- **Exemptions are themselves checked.** The gate fails if an exemption names an
  identifier that *is* used in an example (stale) or one the library does not export
  (typo). Without this the list rots into a permanent excuse.
- **The residual gap is stated, not hidden:** a symbol counts as "used" whenever it
  appears anywhere in an example's datum tree — inert quoted data, a bound variable
  name, anything in non-call position — not only in a genuine invocation. Closing it
  means a scope analyzer distinguishing reference position from literal data, which
  is not worth its cost here.

### 3.4 What the golden files do and do not prove

Expected output generated from behavior and then asserted against that behavior is
self-fulfilling. Two mitigations, neither complete:

- `01` and `04`'s HTML is already pinned byte-for-byte against the real `cmark-gfm`
  CLI and against `markdown->html` by the existing differential suites, so it is not
  self-certified.
- The remainder are read before they are committed.

The gate in §3.3 is the part that cannot be faked, and it is the part that answers
the exit criterion.

## 4. Stress

`tests/test-stress.sps`. Its subject is **accumulation**, which nothing tests today.

- **The repeated loop.** N iterations across all four renderers plus `markdown->ast`
  plus `markdown->sxml`, asserting `live_parsers`, `live_roots`, and `live_buffers`
  (`cmark-gfm-shim.c:43-56`) are zero after *each* iteration and after the loop.
  Every counter assertion in the suite today is single-shot: a per-call leak of one
  buffer satisfies all of them and fails this on iteration two. This is plan §17's
  renderer-buffer-leak risk tested across iterations rather than once.
- **Pathological shapes below the limits** — deep blockquote and emphasis nesting, a
  wide table, one very long line. These run *under* `max-depth`/`max-nodes`, so they
  test robustness, not limit enforcement.
- **Limit boundaries are deliberately not retested.** All three are already covered
  at the boundary: depth at `test-convert.sps:266-269` (exactly at the limit
  converts, one level past raises `too-deep`) and again through the options record at
  `test-convert.sps:571-576`; node count at `test-convert.sps:275-283`; and
  `max-input-bytes` at `test-lifecycle.sps:211-221`, with balanced counters.
  Re-asserting them here would add runtime and no coverage.
- **N comes from the environment** — `CMARK_STRESS_ITERATIONS`, defaulting low
  enough that `make test` stays fast (config in the environment is 12-factor). CI
  raises it. `make test-memory` must lower it: Valgrind is roughly two orders of
  magnitude slower, and a fixed count would make that job unusable.

## 5. Documentation

All README additions are **terse**. In-depth documentation is deferred to a `docs/`
tree in later work; this stage states contracts and points at the design spec and
ADRs for rationale.

### 5.1 The support matrix

`README.org:16` currently claims *"Chez Scheme 10.4.1 or later"*. Design spec §1.2
already identifies that as one developer's machine version transcribed as a floor
and never verified, and records the tested floor as **9.5.8**. The README is wrong
today and the matrix replaces it:

| Platform | Chez | Acquisition | Memory evidence |
|---|---|---|---|
| macOS/ARM64 (Homebrew) | 10.4.1 | pkg-config *and* vendored | ASan; **no leak claim** (ADR-0003) |
| Linux/x86_64 (Ubuntu apt) | 9.5.8 | vendored | Valgrind clean |

plus `cmark-gfm` in `0.29.0.gfm.x`, pinned to `0.29.0.gfm.13`, range
`(#x001d0000 . #x001dffff)`.

**The matrix is checked, not asserted in prose.** A CI step compares the versions the
job actually ran against the table and fails with an instruction to update it. The
trade is explicit: a runner-image bump becomes a one-line README change instead of a
claim going quietly stale. That is the right failure direction, and it keeps faith
with `ci.yml`'s existing decision to *record* versions rather than pin them — the
document now tracks the recording instead of competing with it.

### 5.2 Ownership

A short contract section: AST objects are Scheme-owned; no native pointer escapes;
borrowed native strings are copied before root cleanup; a document is dead outside
its scope; renderer buffers are copied and freed. Rationale stays in design spec §5.

### 5.3 Linking

Plan §14 requires documenting static versus dynamic linking. The README contains no
mention of either today. One paragraph: both acquisition paths link **dynamically**;
the vendored build produces shared libraries and the shim links them with an
explicit rpath; static linking is *impossible* rather than merely unchosen, because
cmark's static archives hide every symbol and ADR-0002 requires those symbols to
resolve from Scheme at runtime (ADR-0001, amended).

### 5.4 Licensing and the install caveat

A `NOTICE` file reproducing `vendor/cmark-gfm/COPYING` (BSD-2, John MacFarlane,
2014) beside the binding's own BSD-3, satisfying plan §14's requirement to include
license notices for the binding and its native dependency.

The Akku caveat from design spec §6.6 becomes README text rather than something
discovered at install time: the manifest declares libraries and dependencies, Akku
distributes source and cannot build the native shim, and 1.0's install is clone plus
`make build`.

## 6. The clean-machine CI job

A third job, `clean-install`, running in a bare `ubuntu:24.04` **container** rather
than on the GitHub runner image — the runner image arrives with a toolchain already
present and would prove nothing about a clean machine.

Steps, in order:

1. Install the documented prerequisites.
2. Check out with submodules.
3. **Before building**, import `(cmark gfm)` under `CHEZSCHEMELIBDIRS=src:fallback`
   and assert `&cmark-shim-unavailable` with reason `'not-built`. This is the
   fallback exercised in the exact situation it exists for, on a machine that is
   genuinely unbuilt rather than synthetically so.
4. `make build`.
5. `make examples`.

It never runs `make deps`. That omission is what makes "a consumer needs no dev
dependencies" falsifiable rather than merely stated.

**The prerequisite list has one copy.** Rather than police duplication between
README's prerequisites and the job's `apt-get` line, the list lives in
`packaging/debian-prereqs.txt`; the job installs from it and the README points at
it. Nothing to drift, so nothing to check.

## 9. Invariants enforced as checks, not comments

Per AGENTS.md, each rule this stage introduces is executable:

| Invariant | Enforced by |
|---|---|
| The fallback and generated config declare the same library, exports, and version range | `make check-config` |
| Every public export appears in a runnable example | `tests/test-example-coverage.sps` |
| Every coverage exemption is real, used nowhere, and actually exported | same suite |
| Examples need no dev dependency | `make examples` sets `CHEZSCHEMELIBDIRS=src:fallback` only |
| The documented support matrix matches what CI ran | CI matrix step |
| The documented install sequence works from nothing | `clean-install` job |
| An unbuilt tree names its own remedy | `clean-install` step 3; `test-shim-loading.sps` |
| The prerequisite list cannot drift from the job | one copy — `packaging/debian-prereqs.txt` |
| Nothing accumulates across repeated renders | `tests/test-stress.sps` |

## 10. Planned mutations

Each new assertion must be watched failing before it is called done, per AGENTS.md,
by breaking the specific decision it guards outside the repo and confirming the
failure is the predicted one, named.

| Mutation | Must break |
|---|---|
| Fallback `shim-path` `#f` → a real built shim path | the `'not-built` reason assertion (not merely "raised something") |
| `resolve-shim-path`'s new clause deleted | same assertion, via loader error instead of condition |
| `CHEZ_LIBDIRS` reordered to `fallback:src` | every native suite, by loading the fallback over a real build |
| Remove one export from the fallback config | `make check-config` |
| Change the fallback's version-range literal | `make check-config` |
| Delete one example's use of a covered export | `test-example-coverage.sps`, naming that identifier |
| Add an export to `gfm.sls` with no example | same suite |
| Exempt an identifier that an example does use | the stale-exemption assertion |
| Skip one `free-buffer` call in the shim | `test-stress.sps` loop, on iteration two |
| Make one example import `(srfi :64)` | `make examples`, with library-not-found — this is what proves the no-dev-dependency claim |
| Edit one README matrix version | the CI matrix step |

## 11. Deliberate coverage gaps

- **A symbol counts as covered from any position in an example's datum tree, not
  only a genuine invocation** — inert quoted data or a bound variable name both
  count (§3.3). Cost of closing it (a scope analyzer) exceeds the risk.
- **Golden example output is partly self-certified** (§3.4). Only the HTML paths have
  an independent oracle.
- **`CHEZ_CMARK_GFM_SHIM` in an unbuilt tree is macOS-only** (§2.4). Documented,
  not fixed; ADR-0014's successor design owns it.
- **The matrix check proves agreement with the CI run, not that the documented floor
  still works.** If a runner image drops Chez 9.5.8, the check forces the matrix to
  change; it cannot keep 9.5.8 tested. A pinned-floor job would, and is not in this
  stage.
- **`invalid-override` conflates three override failures** (§2.3): a relative path, an
  empty string, and an absolute path that does not exist all report the same reason.
- **Akku installation is unproven.** 1.0 claims clone + `make build` and nothing
  more (§1.1).
